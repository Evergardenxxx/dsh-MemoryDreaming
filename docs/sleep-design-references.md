# 睡眠整理与梦境：已核对的参考和工程边界

核对日期：2026-10-27。本文区分公开工程机制、睡眠研究和本项目的设计选择。睡眠整理可以采用成熟的后台记忆管理路线；随机重组的梦境属于产品设计，不能据此声称已经模拟或证明人类梦的生物功能。

## 人类睡眠研究能借鉴到什么程度

[Rasch 与 Born，About Sleep's Role in Memory，2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC3768102/) 综述了睡眠与记忆巩固、重激活、整合的关系。它支持“在减少外界输入的阶段回放已有材料、将新内容联系到已有知识”的设计启发。软件里重跑抽取、去重、摘要和来源校验是工程对应物，并不复制神经系统的过程。

[Tononi 与 Cirelli，Sleep and the Price of Plasticity，2014](https://pmc.ncbi.nlm.nih.gov/articles/PMC3921176/) 讨论突触稳态假说（SHY）：清醒学习后的连接强度需要在睡眠中重新平衡，选择性保留与整合重要结构。这是关于生物机制的假说与证据综述，不是要求软件随机删除低频记录的通用算法。文中也讨论了在缺少环境反馈时强化自身“幻想”的危险；对本项目而言，生成的梦不得成为新增事实的独立证据。

[Nir 与 Tononi，Dreaming and the brain，2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC2814941/) 区分梦的体验、神经相关和功能解释。梦里可出现清醒经历的片段及新组合，但“梦境本身是否承担特定记忆功能”不能等同于睡眠有助巩固。该综述并列讨论了不同功能观点。本项目可以借用片段重组的表现形式，不能将随机拼接、重要性权重或衰减参数宣传成已验证的人类梦机制。

因此采用两条处理路径：

```text
已授权窗口中的原始对话事件
    ├─ 来源校验 → 四类候选 → 去重/摘要/检查点 → 有依据的记忆整理
    └─ 有效来源碎片 → 分层抽样/随机重组 → 明确标记的梦境派生物
```

第一条负责事实和工作状态，第二条负责苏醒后的梦境表达。梦能记录“这次整理处理过哪些材料”，也能提供以后探索的关联线索；它不能证明梦里的新人物、地点、关系或经历发生过。

## 本轮实现应保持的约束

1. **指令只由真实用户消息触发。** 按窗口启用、关闭、睡眠和苏醒应采用精确匹配的单独指令；引述、代码块、工具返回、检索记忆和模型回复中的相同文字不触发开关。默认未启用的窗口不采集正文、不抽取、不注入记忆，不将其他窗口的启用状态当作本窗口授权。
2. **全量清点与有界模型输入分开。** 睡眠整理可以覆盖该窗口自启用以来已保存的所有事件，但用持久 cursor、固定事件上界和有限批次逐段处理。不能在上下文已经耗尽时又把完整窗口历史一次注入给同一个 LLM。已经耗尽的模型调用无法继续时，后端仍应能形成待处理检查点和明确的降级结果。
3. **睡眠任务冻结来源与随机种子。** 用 sleep_id/request_id 幂等关联任务，记录 scope、conversation、事件边界、来源版本和 mutation epoch。随机选择只在首次规划时发生，重试沿用该计划；崩溃恢复不重新抽梦，也不重复应用巩固收益。
4. **梦使用独立派生存储。** 梦有 `generated_fiction` 一类显式标签、生成时间、来源列表、算法版本与抽样种子。它不写入语义事实或核心，也不能充当 AND/OR 支持组的事实根。苏醒时以“梦境记录/我梦到……”介绍，不能讲成“我们以前真的去过……”。
5. **真假不随回放次数改变。** 可以给实际重放且来源有效的记忆施加有上限的 retrieval_strength 调整；不因出现在梦里提升 epistemic_status、truth/confidence、importance 或 access_count。`last_used_at` 表示被实际使用时，也不应被睡眠回放伪造。多次睡眠需有每记录/每周期上限，避免反复发指令刷高权重。
6. **遗忘优先于巩固和梦境。** 源事件被遗忘、来源片段被抑制、记忆被改写或核心版本失效后，旧梦在苏醒读取时重新校验。无法定位哪些句子受到影响时，整段旧梦保守隐藏或重新生成，不能保留它对已遗忘事实的改写。只有修改状态/索引还不够，缓存、已排队文本和生成结果同样受来源代次保护。
7. **来源要精确到片段。** 一条用户消息可能同时含“名字”和“喜欢猫”，遗忘偏好不应撤销不重叠的名字片段。记录 `event_id + source_span`，不要只因共享同一事件就把整个事件中的其他事实一起遗忘；旧来源缺少区间时明确采用保守隔离。
8. **自动遗忘保持可逆。** 睡眠中的低重要/长期未使用内容可降低默认召回强度或降入冷层，但不自动物理删除、不抑制用户明确要求保留的事实、不改写核心。记录 before/after、原因、来源版本和 sleep_id；回滚时复核当前值，避免覆盖后来用户使用或纠正带来的更新。永久遗忘继续走现有明确授权入口。
9. **不重要的碎片也有抽样机会。** 可按近期、重要、低重要/旧记录分层，无放回抽样，并保留每层配额；不足时少取，不填造来源。具体比例和权重是可调工程政策。随机内容无足够来源时返回“没有可回顾的梦”，不要为营造人格连续性编造共同经历。
10. **LLM 整理只能提出候选。** 在固定 schema 中列出四类记忆、证据 span、未完事项、冲突和可选梦文；服务端复核范围、版本、格式与依据，核心变化和永久遗忘仍需可信宿主审批。模型返回“已整理”不等于数据库事务完成，完成状态以持久回执为准。

## 建议的验收场景

| 场景 | 必须观察到的结果 |
|---|---|
| 两个窗口中只启用 A | B 的输入不写入记忆库、没有插件资料块，A 正常恢复 |
| 在引号或工具结果中出现启用/睡眠指令 | 不改变窗口状态、不启动任务 |
| 睡眠期间用户要求遗忘一个来源 | 在途生成不能提交旧来源；苏醒不泄露原片段或其改写 |
| 进程在整理或发布阶段退出 | 任务可继续或明确失败；同请求重试不重复增加强度、不写两份梦 |
| LLM 将梦写成“用户住在梦里城市” | 作为事实候选拒绝或隔离；梦可保留 fiction 标签但不写事实库 |
| 重要与低重要有效片段充足 | 记录抽样分层与来源，随机组合可复现；不是只抽热门记忆 |
| 连续重复睡眠 | 命中幂等或受周期上限约束，access_count 与核心版本不因梦自行增加 |
| 原消息包含多个独立事实 | 遗忘一个片段不会把不重叠事实误当同一断言；旧梦有不明定位则保守隐藏 |
| 上下文已满 | 后端保存整理计划和进度；不承诺一个已无法生成的前台调用还能完成全部整理 |

这些约束针对的是可检验的工程行为。生成梦的生动程度、长期人格连续性、巩固/衰减参数的效果仍需真实使用评估；增加一个人类睡眠术语并不能替代数据和验收。
