# 原生桌面记忆管理

首版管理页面随引擎0.30.0、原生插件0.17.0提供，数据库仍为schema27。入口位于Harness侧栏的“记忆管理”。页面使用宿主共享的客户端运行时、原生面板和拥有者RPC，不启动HTTP服务，不向模型注册MCP工具，也不把页面内容加入对话上下文。

当前页面管理插件配置中固定的用户、角色、关系和领域。窗口选择器只选择一个正在运行的普通对话窗口，不切换角色或数据库；没有运行中的窗口时，仍可浏览该绑定的记忆、审批候选、查看诊断或初始化空角色。

## 打开页面与首次设定

1. 按[快速上手](quickstart.md)安装生成的原生插件目录，重载Harness。
2. 点击侧栏“记忆管理”，在“绑定与诊断”中核对用户、角色、关系和领域。
3. 如果绑定从未建立身份或关系核心，填写名字、身份、称呼和相处设定，核对预览后确认初始化。
4. 选择目标对话窗口，点击开启按钮或在对话中发送独立消息`记忆开启`。

初始化将明确填写的设定作为用户操作来源，与两个核心原子保存。任何已有核心，包括来源已隐藏或遗忘的核心，都不能用初始化覆盖；已有资料应走受控修订/审批。新窗口仍默认关闭，打开管理页面不会为全部窗口启用记忆。

## 页面能力

| 页面 | 当前可操作内容 | 边界 |
|---|---|---|
| 记忆 | 按四类记忆筛选、文字搜索、分页、查看结构化正文与来源；填写理由后确认纠错或遗忘 | 搜索是管理列表的文字过滤；完整混合检索由引擎的对话检索入口负责 |
| 待审候选 | 查看核心、记忆变更、自传、成长、相处偏好五类已有候选，单独确认或拒绝 | 页面不会自动产生新候选；推测不等于用户同意，未展示完整的候选不能直接批准 |
| 角色 | 查看有效自传、未完承诺、已确认偏好和表达成长 | 本版为只读概览，完整创建、编辑、撤回表单尚未提供 |
| 睡眠与梦境 | 查看持久睡眠批次、完成状态和有效梦境 | 梦明确标记为`generated_fiction`，不能作为事实或人格依据 |
| 绑定与诊断 | 查看固定绑定、核心资料、记忆计数、后台任务及健康缺口；初始化空角色 | 不暴露密钥，不支持在页面切换角色或选择任意数据库 |

正文、来源和候选均通过现有来源、版本、作用域及遗忘检查后返回。部分长内容会显示截断状态；截断正文不能直接作为完整纠错内容保存。已遗忘资料不会通过“查看详情”重新恢复。管理列表可能包含已结束有效期的历史记忆，应同时查看状态与有效性。

## 窗口按钮与睡眠进度

窗口区提供开启、关闭、睡眠和苏醒操作。按钮通过宿主真实`sessionController.prompt`提交对应用户指令，继续使用原有生命周期、用户来源和预算检查。操作带窗口版本；窗口已经改变或正在处理消息时，页面要求刷新或等待，不直接覆盖其状态。

`accepted`只表示指令已被宿主接收并入队，不能据此认定记忆已经开启、睡眠已经完成或梦已经保存。应等待对话回执，并结合后续窗口快照、审阅批次和梦境状态核对结果。

睡眠期间可请求“停止整理”。`cancel_requested`表示停止请求已发出，最终状态仍以后续快照为准。已成功审阅的批次保留，再次发出睡眠指令可继续；未完成的整理不会冒充完整巩固。关闭页面只停止轮询和页面请求，不撤销已经提交的管理操作或窗口指令。

## 审批、纠错与遗忘

每次写入先展示待提交内容，再由用户明确确认。页面携带刚刚读取的版本或修订指纹；来源、资料或窗口状态发生变化时，旧操作会失败，需要重新读取核对。重试使用同一操作编号，不应因一次超时重复创建资料。

桌面确认是单独保存的用户操作事件。核心/变更候选原来的用户请求仍然是原提议依据；新的点击确认不会伪装成那条原话，也不会让模型获得审批权限。纠错和遗忘复用已有领域服务与回执，保留撤销传播和遗忘屏障。

事实遗忘主要是本地持久抑制，不表示已经擦除外部备份或收回已发送给模型的文字。窗口关闭也不删除已存记忆。需要清除、迁移或恢复档案时，遵循[遗忘说明](fact-suppression.md)和[档案说明](narrative-continuity.md)；本版尚无图形化档案导入导出。

## 接入与验证边界

客户端使用Harness原生`main`与`sidebar.panellist`插槽，经拥有者RPC访问`memorydreamingDesktop/request`。原生控制器固定身份范围并转发到本地JSONL桥接；Python管理服务复用`ViewReader`和现有审批/变更服务。非拥有者调用被拒绝，页面参数不能覆盖用户、角色、关系、领域或数据库路径。

2026-10-28本地验证结果：

- 773项工程回归通过，覆盖管理服务、来源/范围/版本、审批重试、原生控制器和客户端加载。默认模型策略关闭时，拥有者仍可审阅已有候选，模型权限不扩大。
- 安装版运行时27条隔离路径通过，其中新增12条验证真实Cordis Gateway的拥有者鉴权、取消、卸载，以及客户端注册表发现和服务实际lazy bundle。
- Chromium浏览器12条操作路径通过，共71次请求、3批睡眠审阅。四类筛选/分页/来源、初始化、成长审批、纠错/遗忘、XSS防护、睡眠/苏醒、390px暗色页面、轮询草稿与卸载重挂载均有断言。

浏览器使用真实管理控制器、Python桥接、SQLite和睡眠编排；宿主指令接纳及模型输出是确定性测试适配器，全部资料为合成数据。安装版验收运行公开模块，未替换用户应用。当前用户Electron窗口、登录模型和长期陪伴效果仍需独立验收。

## 可复跑的验证

在仓库根目录执行基础回归与客户端一致性检查：

```powershell
python scripts/build_native_client.py --check
python -m unittest discover -s tests -q
```

安装版公开运行时验收需要本机Harness和兼容的Node.js：

```powershell
python scripts/accept_installed_harness.py --asar "C:\Users\YOUR_USER\AppData\Local\Programs\DeepSeek Harness\resources\app.asar" --desktop --output dist/desktop-preview/installed-runtime.json
```

浏览器验收需要可用的Playwright模块和Chromium浏览器，它们不是插件运行依赖。默认从Node模块路径解析`playwright`，也可显式指定其`index.js`绝对路径：

```powershell
node scripts/desktop_browser_acceptance.mjs --playwright-module "C:\path\to\playwright\index.js" --channel msedge
```

使用其他Chromium可传`--chromium`及其可执行文件路径。脚本将JSON报告与四张截图写入`dist/desktop-preview/`，临时服务只供本次测试，结束时清理。报告保留`real_electron=false`、`live_model=false`，避免将隔离验证误当作实际账号验收。
