# 原生桌面记忆管理

管理页面当前随引擎0.33.0、原生插件0.20.0提供，数据库仍为schema27。入口位于Harness侧栏的“记忆管理”。页面使用宿主共享的客户端运行时、原生面板和拥有者RPC，不启动HTTP服务，不向模型注册MCP工具，也不把页面内容加入对话上下文。

当前页面管理插件配置中固定的用户、角色、关系和领域。窗口选择器只选择一个正在运行的普通对话窗口，不切换角色或数据库；没有运行中的窗口时，仍可浏览该绑定的记忆、审批候选、查看诊断或初始化空角色。

## 打开页面与首次设定

1. 按[快速上手](quickstart.md)安装生成的原生插件目录，重载Harness。
2. 点击侧栏“记忆管理”，在“绑定与诊断”中核对用户、角色、关系和领域。
3. 如果绑定从未建立身份或关系核心，填写名字、身份、称呼和相处设定，核对预览后确认初始化。
4. 选择目标对话窗口，点击开启按钮或在对话中发送独立消息`记忆开启`。

初始化将明确填写的设定作为用户操作来源，与两个核心原子保存。任何已有核心，包括来源已隐藏或遗忘的核心，都不能用初始化覆盖；已有资料应走受控修订/审批。新窗口仍默认关闭，打开管理页面不会为全部窗口启用记忆。

## 页面能力

| 页面 | 当前可操作内容 | 边界 |
|---|---|---|
| 记忆 | 按四类记忆筛选、文字搜索、分页、查看结构化正文与来源；填写理由后确认纠错或遗忘 | 搜索是管理列表的文字过滤；完整混合检索由引擎的对话检索入口负责 |
| 待审候选 | 查看核心、记忆变更、自传、成长、相处偏好五类已有候选，单独确认或拒绝 | 页面不会自动产生新候选；推测不等于用户同意，未展示完整的候选不能直接批准 |
| 角色 | 核心身份/关系字段编辑、来源及版本历史；四类资料目录、表单、状态操作及概览 | 来源失效或字段未完整展示时禁止核心编辑；自传与承诺终态不可改写 |
| 睡眠与梦境 | 查看持久睡眠批次、完成状态和有效梦境 | 梦明确标记为`generated_fiction`，不能作为事实或人格依据 |
| 绑定与诊断 | 查看固定绑定、核心资料、记忆计数、后台任务及健康缺口；初始化空角色 | 不暴露密钥，不支持在页面切换角色或选择任意数据库 |

正文、来源和候选均通过现有来源、版本、作用域及遗忘检查后返回。部分长内容会显示截断状态；截断正文不能直接作为完整纠错内容保存。已遗忘资料不会通过“查看详情”重新恢复。管理列表可能包含已结束有效期的历史记忆，应同时查看状态与有效性。

## 核心身份与关系编辑

在“角色”页上方选择“身份核心”或“关系核心”，点击“编辑核心”重新读取当前版本。既有字段名称锁定，可修改值、移除当前设定，或添加新的字段。文本按原样保存；数组、对象、数字、布尔值及null使用“JSON结构”类型，避免把结构化设定全变成字符串。

身份核心由同一角色的各关系共用，关系核心只用于当前绑定关系。页面会显示这一范围差异；它仍不能切换用户、角色或数据库。尚未建立的空角色继续通过初始化流程设置。

填写“核心修改理由”，点击“准备保存核心”检查逐项的新增、修改、移除和前后值，再点击“确认提交”。预览期间字段锁定；“返回编辑”保留草稿。保存使用刚读取的版本和来源指纹，两处同时修改时后提交的旧版本会失败；回执中断可原样重试，不追加第二次版本。修改事件、核心版本、字段修订和无正文回执在同一事务内保存，管理事件不进入聊天抽取队列。

“移除此字段”仅从当前设定中移出，不等于遗忘，旧版本仍可以追溯。字段来源或修改授权被遗忘、撤回或超出当前活动权限后，历史正文与理由会重新检查并隐藏；删除修订保留，不能因来源失效而自动回退到旧设定。已有隐藏字段不能通过猜测名称重新写回。

“核心字段来源”和“核心版本历史”提供字段依据及历史对照。过长内容显示截断状态，来源失效只说明隐藏情况，不暴露隐藏字段名称。页面不会将这些内容或管理接口添加到LLM工具目录。

内部动作 `core_editor` 与 `core_save` 由独立 `DesktopCore` 编排，复用既有核心版本、字段双时间修订和遗忘屏障。数据库模式无需升级。普通模型候选仍须走原审批流程；页面编辑不向模型开放直接修改核心的权限。

## 四类角色资料管理

进入“角色”，选择自传、承诺、相处偏好或成长。点击“新建”或选择目录中的记录，填写表单与操作理由；“准备保存”只显示预览，点击“确认提交”后才写入。无需手写JSON，也不必开启对话。偏好名称/场景和成长字段是记录标识，编辑时锁定；承诺的承担方和类别也不能在修订中改变，应另建承诺。

| 资料 | 表单内容 | 状态与历史 |
|---|---|---|
| 自传 | 标题、内容、视角、真实叙述/共同虚构、可选发生时间 | 可修订有效记录或撤回；撤回后保留记录头与历史，若要重新建立应新建。共同虚构不会升级为真实事件 |
| 承诺 | 内容、承担方、类别、可选到期时间/触发事件 | 修订与新的用户确认原子保存；可完成或取消，终态不能编辑，历史继续可查 |
| 相处偏好 | 名称、场景、内容 | 可更新或撤销；撤销后不回退旧偏好。重新确认时以当前版本填写新内容 |
| 表达成长 | 回应风格、讲故事、互动习惯或支持方式 | 可更新或撤销，不改身份核心。同一字段24小时内再次改变默认拒绝，明确纠正可勾选“允许近期明确纠正” |

可选时间须带时区，例如`2026-10-28T20:00:00+08:00`。偏好场景是显式保存的范围；普通原生回合仍读取`default`，此表单不意味着已经实现自动场景选择。

版本历史显示最近记录供查看与对照，最多50项，超出响应预算或条数会提示未全部展示。已知状态、历史字段和内容性质使用中文标签，正文和标题保持用户原文。来源失效的正文会隐藏；撤回不是遗忘，历史仍可包含未被遗忘的旧内容。不能用新建或旧版本覆盖隐藏记录；遗忘后的重新学习仍需专门授权流程。

每次表单提交将本次用户填写的内容保存为独立管理事件，与领域变更和无正文的持久回执在同一事务中提交。它是本次明确设定的来源，不伪装成早先的聊天原话。管理确认保留事件和审计记录，但不进入普通对话抽取队列，避免将表单JSON中的共同虚构、审批说明等再次抽取为事实。两个窗口同时编辑时，后提交的旧版本会失败，草稿保留供核对；传输中断后用原确认重试不会再次推进版本。

内部管理动作是`role_catalog`、`role_history`、`role_save`和`role_transition`，由`DesktopRoles`复用既有四类领域服务。它们不属于模型工具，页面参数不能提供替代身份或来源。只读管理连接不能提交写操作。

## 窗口按钮与睡眠进度

窗口区提供开启、关闭、睡眠和苏醒操作。按钮通过宿主真实`sessionController.prompt`提交对应用户指令，继续使用原有生命周期、用户来源和预算检查。操作带窗口版本；窗口已经改变或正在处理消息时，页面要求刷新或等待，不直接覆盖其状态。

`accepted`只表示指令已被宿主接收并入队，不能据此认定记忆已经开启、睡眠已经完成或梦已经保存。应等待对话回执，并结合后续窗口快照、审阅批次和梦境状态核对结果。窗口区以“已审阅3/3批”等文字显示睡眠进度。

睡眠期间可请求“停止整理”。`cancel_requested`表示停止请求已发出，最终状态仍以后续快照为准。已成功审阅的批次保留，再次发出睡眠指令可继续；未完成的整理不会冒充完整巩固。关闭页面只停止轮询和页面请求，不撤销已经提交的管理操作或窗口指令。

## 审批、纠错与遗忘

每次写入先展示待提交内容，再由用户明确确认。页面携带刚刚读取的版本或修订指纹；来源、资料或窗口状态发生变化时，旧操作会失败，需要重新读取核对。重试使用同一操作编号，不应因一次超时重复创建资料。

桌面确认是单独保存的用户操作事件。核心/变更候选原来的用户请求仍然是原提议依据；新的点击确认不会伪装成那条原话，也不会让模型获得审批权限。纠错和遗忘复用已有领域服务与回执，保留撤销传播和遗忘屏障。

事实遗忘主要是本地持久抑制，不表示已经擦除外部备份或收回已发送给模型的文字。窗口关闭也不删除已存记忆。需要清除、迁移或恢复档案时，遵循[遗忘说明](fact-suppression.md)和[档案说明](narrative-continuity.md)；本版尚无图形化档案导入导出。

## 接入与验证边界

客户端使用Harness原生`main`与`sidebar.panellist`插槽，经拥有者RPC访问`memorydreamingDesktop/request`。原生控制器固定身份范围并转发到本地JSONL桥接；Python管理服务复用`ViewReader`和现有审批/变更服务。非拥有者调用被拒绝，页面参数不能覆盖用户、角色、关系、领域或数据库路径。

2026-10-28，v0.31本地验证结果：

- 795项工程回归通过，覆盖管理服务、来源/范围/版本、审批重试、原生控制器和客户端加载。默认模型策略关闭时，拥有者仍可审阅已有候选，模型权限不扩大。
- 安装版运行时27条隔离路径通过，其中新增12条验证真实Cordis Gateway的拥有者鉴权、取消、卸载，以及客户端注册表发现和服务实际lazy bundle。
- Chromium浏览器21条操作路径通过，共284次请求、3批睡眠审阅。四类筛选/分页/来源、初始化、成长审批、纠错/遗忘、XSS防护、睡眠/苏醒、390px暗色页面、轮询草稿与卸载重挂载均有断言。

新增角色路径覆盖四类新建/编辑、共同虚构标签、承诺完成/取消、撤回后目录和历史、两个管理客户端的版本冲突、保存成功但回执丢失后的原请求重试，以及偏好/成长撤销后重新填写确认。22项后端角色回归还覆盖确认和回执写入失败的整体回滚、只读/范围限制、来源失效与大体积中文历史；真实独立连接后台线程验证8条管理事件不进入抽取队列，而普通聊天仍正常形成记忆。

2026-11-03，v0.33本地验证结果：

- 850项工程回归通过，其中新增21项核心管理回归，覆盖新增/移除/类型、来源与历史、深层JSON完整往返、版本及同版本来源变化、跨运行时重试、遗忘后拒绝重放和事务失败回滚。
- 核心与来源预览过大时，读取与保存共用同一完整性限制；未展示的内容不能借来源指纹直接覆盖。安全整数、来源活动/关系权限及猜测旧字段名恢复遗忘内容均有回归。
- 安装版运行时27条隔离路径通过。Chromium浏览器27条操作路径通过，包含320次页面请求、3批睡眠审阅、核心逐项确认/结构化值、删除历史、真实双客户端版本冲突、回执中断重试、轮询焦点与390px暗色编辑。

浏览器使用真实管理控制器、Python桥接、SQLite和睡眠编排；宿主指令接纳及模型输出是确定性测试适配器，全部资料为合成数据。安装版验收运行公开模块，未替换用户应用。当前用户Electron窗口、登录模型和长期陪伴效果仍需独立验收。

## 可复跑的验证

在仓库根目录执行基础回归与客户端一致性检查：

```powershell
python scripts/build_native_client.py --check
python -m unittest discover -s tests -q
```

安装版公开运行时验收需要本机Harness和兼容的Node.js：

```powershell
python scripts/accept_installed_harness.py --asar "C:\Users\YOUR_USER\AppData\Local\Programs\DeepSeek Harness\resources\app.asar" --desktop --output dist/desktop-preview/installed-runtime.json
```

浏览器验收需要可用的Playwright模块和Chromium浏览器，它们不是插件运行依赖。默认从Node模块路径解析`playwright`，也可显式指定其`index.js`绝对路径：

```powershell
node scripts/desktop_browser_acceptance.mjs --playwright-module "C:\path\to\playwright\index.js" --channel msedge
```

使用其他Chromium可传`--chromium`及其可执行文件路径。脚本将JSON报告与十张截图写入`dist/desktop-preview/`，临时服务只供本次测试，结束时清理。报告保留`real_electron=false`、`live_model=false`，避免将隔离验证误当作实际账号验收。
