# 按窗口启用、睡眠整理与苏醒（v0.29 / 原生插件 v0.16）

本版默认不影响普通聊天窗口。只有在某个窗口中发送独立启用指令后，插件才在该窗口保存新输入、恢复核心、检索与注入记忆。同一用户/角色/关系仍共享长期数据库；窗口开关决定参与与否，不改变长期记忆分区。

## 可以直接发送的指令

| 独立消息 | 英文等价指令 | 行为 |
|---|---|---|
| `记忆开启` | `/memory on` | 只启用当前窗口，确认已恢复的身份/称呼；不自动追溯启用前的聊天 |
| `记忆关闭` | `/memory off` | 当前窗口停止记录、检索、注入；清空自己的当前记忆节点，既有数据库记忆保留 |
| `记忆睡眠` | `/memory sleep` | 对当前启用窗口已经本地保存的全部对话分批审阅，生成梦与有限巩固回执，随后保持睡眠 |
| `记忆苏醒` | `/memory wake` | 启用当前窗口、恢复核心和连续性自检卡，并提供同身份范围最近一次仍有效的梦；允许在新窗口发送 |

也接受 `开启记忆`、`关闭记忆`、`进入睡眠`、`苏醒记忆`。默认指令须是整条真实用户消息，允许首尾空白；普通句子中的提及、引述、代码块、检索资料、模型回复或工具结果不触发。睡眠指令在未启用窗口只提示先开启，不自动采集该窗口内容。

最常用流程：

```text
窗口 A：记忆开启
        正常聊天……
        记忆睡眠
        等待“睡眠整理已完成”

窗口 B：记忆苏醒
        可以听梦、恢复身份与长期记忆，然后继续聊天
```

新窗口默认仍关闭，即使窗口 A 已开启。重新打开同一持久会话、重载插件或重启应用，会恢复该会话的开启/关闭/睡眠状态。状态文件只保存 mode、睡眠任务 ID 与代次，位于数据库旁的 `.windows/`，按身份绑定和会话 ID 哈希隔离，不保存聊天正文。损坏状态保守回到关闭。

`activationMode: command` 是安装器与示例默认值。`always` 只保留给明确希望旧全局行为的可信 SDK/兼容测试；默认配置与升级后的缺省值都不会自动启用所有窗口。

关闭只停止插件以后的参与，无法撤销模型在此前请求中已经看到的历史。新窗口默认不读取旧窗口内容；已确认投递的磁盘 outbox 可以继续完成原先已授权的持久化，不会采集关闭后的新消息。

## 睡眠怎样使用 LLM

协调器使用当前窗口已经路由的 `ctx.llm.stream`，所以可以沿用 Harness 的当前登录模型，不要求另外提供 DeepSeek API key。整理请求使用 `purpose=memorydreaming-sleep`，没有工具，只有固定整理规则和当前分片；它们不会重复携带已经很长的前台聊天、项目技能或完整工具目录。

1. 后端清点当前精确 scope + conversation 中所有已保存事件和相关有效记忆，冻结来源、片段位置、版本和随机种子。启用前未保存的聊天不会被暗中导入；其他窗口不会被打包进来。
2. 每个模型批次最多 5000 个原文字性内容字符，单条长消息按最多 3000 字符切片，最多 12 片/批；JSON 外壳另计入请求预算。模型逐批生成工作/情景/语义/程序四类的 `candidate_review` 笔记，逐条引用原事件。
3. 每批先领取持久租约，在事务外调用模型，提交时检查 claim_token、来源版本、遗忘屏障和本批事件全覆盖。已审阅批次不重新调用模型；取消、异常或进程退出后，再发睡眠指令继续。
4. 所有分片都有成功回执后，才原子发布梦、可逆权重调整和完成回执。失败会明确回复“尚未完成”，不以模板梦冒充完整模型整理。
5. 完成确认由插件本地输出；不再用已接近耗尽的整个前台上下文生成一遍确认。若窗口已经触发宿主自动压缩，本地持久来源仍可分批读取。

模型每批默认最多 2048 输出 token、60 秒本地等待上限；`sleepReviewTimeoutMs` 可设 1000..120000。实际供应商配额、费用和可用性沿用当前路由。窗口不晚于上下文硬性拒收前发出指令最可靠；如果宿主连用户指令都无法接收，插件无法自行接管 UI。

分片审阅记录是候选笔记，不自动批准新增事实、人格更新或复杂推断。现有普通抽取、去重、摘要任务继续按各自规则执行；睡眠会对已形成的有效记忆做回放/衰减，而不会把 LLM 摘要当成新的独立事实来源。需要把遗漏内容正式写入四类事实时，仍应走来源校验与审批策略。

## 梦是什么

梦存放在独立 `dreams` 表，固定 `kind=dream`、`epistemic_status=generated_fiction`、`modality=fictional`，不写入四类事实记忆或人格核心，也不能作为事实证据根。

本版的可运行生成方式是带权随机模板：在仍有效的事件/记忆中，按重要性、近期程度和一个正的探索权重做无放回抽样。尽量给高重要与低重要碎片各一个位置，最多六片，再用固定种子乱序拼接成梦。种子与 sleep_id 绑定，网络重试不会重抽或重复发布。SDK 可显式提交 LLM 写出的梦全文，但它仍然仅为虚构；原生默认由苏醒时的前台模型把模板梦自然讲述出来。

没有材料时只生成空白梦的虚构意象，不编造来源。梦不会在普通每次查询中自动出现；只在显式苏醒回执中有界返回。梦的片段任一来源被遗忘、改写或失去支持后，后端整梦保守隐藏，并擦除其生成正文与审阅笔记，避免泄露被遗忘的改写。

苏醒也可携带最多四条短 `candidate_review` 整理笔记，并标记 `approved_facts=false`；预算不足先移除笔记，再裁剪梦。它们提供整理线索，不能替代已批准记忆或原话证据。

v0.29苏醒附加有界连续性自检：核对身份、关系、自传、未完承诺、已确认偏好与表达成长。资料缺失时列出缺口，预算不足时先把状态卡缩成状态/缺口，再按总回执预算裁剪。`记忆自检`可单独查看；`记忆自传/承诺/偏好/成长`等完整JSON指令只在已启用窗口执行，使用方式见[长期角色](long-term-role.md)。梦不会替代自传或用户依据。

## 梦参与巩固与遗忘的方式

- 梦中实际选中、且原始依据有效的记忆可获得最多 `+0.04` 的 retrieval_strength 回放增益，上限 `0.95`；同一记忆每 24 小时最多一次。
- 未选中且重要性 `<=0.35`、从未实际使用、至少 48 小时未新记录的内容，可将 retrieval_strength 乘 `0.96`，最低 `0.15`。
- 每次最多调整 128 条，先覆盖选中的记忆，再填充低重要候选。原始正文、importance、认识论、access_count 和 last_used_at 均不改。
- `sleep_weight_changes` 记录前后值和原因。可信宿主可用 `runtime.sleep.restore_weights(scope, sleep_id)` 撤销；只有当前值仍等于本次写入值时才恢复，避免覆盖后来独立使用产生的变化。

这些数值是可审查的保守工程政策，不宣称是人脑参数。梦出现的次数不会提高事实真实性，自动“遗忘”只是可逆地降低默认召回强度，永久遗忘仍使用明确授权的 `forget_fact/event/scope`。

## 架构与扩展接口

原生 `window-control.js` 处理状态与完整指令；`native-session.js` 处理宿主消息外壳/可替换节点；`sleep-coordinator.js` 只调度有界模型审阅；`durable-files.js` 统一磁盘原子写；`index.js` 连接生命周期事件。后端 `SleepService` 拥有准备、领取、审阅、完成、苏醒与权重回滚，SQLite 迁移在独立的 `storage/sleep-schema.sql`。

可信 SDK 从 `runtime.sleep` 访问 `prepare`、`batch`、`record_review`、`complete`、`wake`、`status`、`restore_weights`。JSONL bridge 使用对应内部操作 `sleep_prepare`、`sleep_batch`、`sleep_review`、`sleep_complete`、`wake`；没有新增 MCP 或模型写工具。完整架构说明见 [系统结构](system-architecture.md)，参考机制见 [来源与研究边界](sleep-design-references.md)。

## 迁移、规模与验收

schema25到26新增睡眠表，v0.29再到27新增长期角色投影表，均为原子升级；既有事件/记忆保持。完整和作用域快照携带睡眠来源、分片回执、梦与权重日志；scope 物理清除级联删除全部睡眠及角色派生物。来源验证缓存只在进程内保存最多 64 项，绑定遗忘/内容代次和下一有效期边界，重启/导入不带缓存，SQL 修改来源也会强制复核。

当前一次清点最多 50,000 个本地事件，超过时明确失败，不截断后冒充全量。50,000 条短事件实测准备约 1265 ms、读取首批约 1.35 ms、提交一批回执约 3.45 ms；这些是本地调度成本，模型调用时间另计。批数很多时总耗时和调用数仍按数据量增长。

工程验证包括默认窗口隔离、完整指令/引述区分、重载、并发关闭、全量长消息分片、租约失效、幂等、梦事实隔离、撤销传播、可逆衰减、每日回放上限、快照与迁移。安装版实际 Cordis/agent/JSONL 验收也跑通了按窗启用、独立模型分批睡眠和跨窗口苏醒；供应商是确定性测试适配器，尚未用用户当前登录模型做新功能 UI 验收。

2026-10-27完整回归738项通过，安装版实际运行时15条路径通过，新增长期角色指令、状态卡与回合资料验证。既有v0.28安装验收已在带空格的临时目录创建真实隔离venv并验证默认关闭、明确开启、分批模型睡眠、跨窗口苏醒与未授权消息不落库；v0.29同样完成隔离venv安装、原生新指令、角色恢复和空白设备档案核验，新增模块/schema与源码逐项匹配。未覆盖用户正在运行的旧安装，也未修改其测试库。
