# 后台预取、运维与投递补偿（v0.26 / 原生插件 v0.13）

这轮完成后台预取调度、持久指标/状态告警、磁盘投递补偿，以及跨数据库 DeepSeek 配额和本地模型硬超时。原生接入保持 Cordis + 本地 JSONL，不增加模型工具目录。

## 后台预取与监控

可信 SDK 可创建 `HostAdapter(runtime, background_prefetch=True)`，再调用 `session.schedule_prefetch(query)`。调度器使用独立线程和 SQLite 连接，每会话只保留最新待执行项，队列最多 32 项。查询原文只在内存中排队；关闭会话取消等待项，进程重启不恢复查询。当前事件被遗忘或作用域代次变化时取消旧工作，检索发布时再次复核来源。调度器关闭和运行时卸载均停止接收工作。

原生 bridge 默认启用 `--auto-prefetch`，零预算保存用户事件后可预热有限查询，`autoPrefetch: false` 可关闭。`schedule_prefetch` JSONL 操作也供可信宿主使用。预取与同步请求使用相同的绑定、当前事件、参数与代次；命中后重新签发本会话引用。它不把预取结果主动放入模型上下文，也不改变事实热度。

`operational_metrics` 按小时保存 cache hit/miss/stale、检索耗时及预取成功/失败计数，保留 30 天；不保存查询或记忆正文。`runtime.operational_trend(scope)` 或 `diagnostics` CLI 可读取。`runtime.check_alerts(scope)` 基于任务失败、摘要状态、审计链、最近预取失败和缓存失效比创建固定告警码，重复检查更新同一行，恢复后标记 resolved；不会向外发送消息。运维表不会使检索缓存自行失效，也不会随主数据快照迁移。

```powershell
python -m memorydreaming --db path/to/memory.db diagnostics --user u1 --character c1 --relationship r1
```

## 持久投递补偿

原生插件收到已提交的 `assistant/message` 时，只提取可见 text，先同步写入数据库旁的 `<database>.outbox/<binding-hash>/`，对文件执行 fsync，再异步调用 bridge。写入大小上限 1 MiB，最多 256 个待处理文件。确认写入数据库后删除文件；进程退出、超时和管道错误保留条目，启动后或每 5 秒重放，每批最多 32 项。已提交但回执丢失时，使用同一 message_id/user_event_id/正文/状态幂等重试。

队列绑定用户、角色、关系和领域；条目保留实际观察到的投递时间，重放不会把过去的回复记成重放时发生。内容摘要用于识别文件损坏，重复 ID 不允许换正文。业务拒绝、无效文件和过期投递会删除正文，只保留固定错误码，拒绝标记最多保留 128 条。插件通过 `memorydreaming/health` 向可信宿主报告队列故障码；磁盘满或队列满会明确失败，不宣称已经持久保存。

`prepare_turn` 生成仅供宿主使用的 `delivery_guard`，绑定真实用户事件和相关范围的遗忘代次。入库回放时复核用户事件未被遗忘、范围仍可见、屏障仍相同；不符返回 `STALE_DELIVERY`，旧正文清除，不恢复被撤销内容。普通新消息和新查询不会使旧投递失效。

边界：未提交的 UI 流式片段不采集；应用在消息事件到达插件前已崩溃仍可能丢失。队列是本地私密数据，使用系统账号文件权限，未做静态加密；逻辑遗忘后的旧排队文件在下次校验时清除，不代表备份或外部上下文已擦除。插件不能推断模型实际使用了哪些记忆，`used_references` 继续为空。

## 跨数据库配额

默认保留原同库闸门。设置 `MEMORYDREAMING_DEEPSEEK_QUOTA_DB` 后，不同记忆数据库可共享一个单独的本地 SQLite 配额库。端点和凭据只以该库密钥的 HMAC 区分；模型、用户与正文不写入配额表。

`MEMORYDREAMING_DEEPSEEK_RPM` / `..._TPM` 默认 0，表示不启用该限制。非零时按滚动 60 秒记录请求和保守 token 预留；等待并发名额、最小间隔、Retry-After 与配额均不持有记忆库写锁。失败调用也保留本分钟使用量，避免重试绕过额度。多进程配置冲突取更严格值。一次调用预留超过 TPM 上限时返回不可重试配置错误。

TPM 预留按输入 UTF-8 字节、schema/外壳余量及最大输出计算，明确不冒充目标 tokenizer 精确计量，也不冒充供应商实际用量。共享文件只适用于本机可靠文件系统，不实现跨服务器配额协调。

## 本地模型硬超时

运行时默认以独立持久 Python 进程加载和编码可选 SentenceTransformer 模型。`MEMORYDREAMING_EMBEDDING_TIMEOUT_SECONDS` 默认 30 秒，范围 0.1..300，涵盖等待编码锁、IPC、加载与编码。超时终止本项目的编码 worker，下一次调用重新启动；模型缺失或失败继续走已有降级与缓存保护路径。运行时关闭释放 worker。Linux 使用父进程退出信号，Windows 监听父进程句柄，使 bridge 退出后自己的编码 worker 跟随退出。

直接实例化的 `SentenceTransformerEmbedder` 仍是同步底层适配器；默认 Runtime 才使用隔离版本。用户自行注入的任意 Embedder 由调用方负责终止语义。没有下载/执行真实权重；真实中文质量和阈值校准仍待进行。
