# 持久事实抑制（v0.6）

这一阶段实现算法规格 G 节的第一部分：忘记某项事实后，重启、更换抽取器版本或重建索引不会直接把它重新带回来。它是 `logical_suppressed`，**没有实现原始消息、备份或远端模型历史的擦除**。

## 使用

```python
from memorydreaming import ForgetSelector, MemoryRuntime

with MemoryRuntime(db_path=".memorydreaming/memory.db") as memory:
    receipt = memory.forget_fact(ForgetSelector(memory_ids=["mem_xxx"]))
    print(receipt.erasure_level)       # logical_suppressed
    print(receipt.tombstone_ids)       # 持久抑制标记
    print(receipt.core_fields_removed)
    print(receipt.conservative_event_ids)
```

旧 `forget(selector)` 入口现在调用 `forget_fact`。CLI `forget mem_xxx` 输出同一结果的 JSON。按 ID 的本地 API 仍假设调用方可信；这不是已经开放给 LLM 的工具。

抑制范围是目标记录的完整 scope：用户、角色、关系、活动、领域都精确匹配。同范围内同一断言的其他旧副本也会被删除；不会自动扩展到另一个关系或活动。更宽范围的用户请求由未来宿主解析选择器，不能由模型随意提供 user_id。

同一断言的全部旧副本先补入来源账本，再计算片段重叠。未来新消息中匹配受抑制断言的候选也会补入来源，之后从这些消息换记忆类型或改写抽取仍受片段保护；同批来源收集先于写入，避免候选顺序改变结果。

## 稳定断言与来源片段

抑制账本记录规范化断言的 HMAC 指纹。规范化使用 Unicode NFKC、空白归一和大小写折叠；语义记忆取 subject/predicate/obj/scope_note，连同类型和模态生成表示。抽取器版本、候选键、说话者元数据和随机记忆 ID 不参与指纹，所以更换这些字段不能让同一断言复活。HMAC 密钥保存在该数据库的 schema_meta；指纹不是匿名化或物理擦除保证。

规则抽取器现在保存原始正文的 Unicode 码点区间，MemoryDraft 使用 `source_span=(start,end)`，MemoryItem 使用 `source_spans={event_id: [[start,end], ...]}`。去重合并同时保留多个来源的区间。

例如 `我叫林鸥。我喜欢猫。` 中两项事实有独立区间。忘记偏好会阻止同一片段被重新抽成偏好或另一种记忆类型；名字的片段不重叠，可以保留。未提供 source_span 的新候选引用了受影响消息时会被隔离，不能只靠换正文绕过遗忘。

旧记录没有区间时，账本将该来源标记为定位不明，返回 conservative_event_ids。此时会保守隔离受影响来源的相关记录/新候选，可能隐藏同消息中的其他内容，但原始消息正文仍保留。这一行为需要宿主向用户解释；不能声称精准删除了一个片段。

不同断言有多个独立事件来源时，当前按 OR 语义保留仍有未抑制来源的内容。选定断言本身则始终受抑制，不依靠另一条相同断言的旧来源恢复。跨独立事件的任意同义改写尚无统一语义断言键保证；当前防护依赖规范化相同断言或已知受抑制来源片段。

## 核心字段与隔离

`propose_core_update` 增加 `field_evidence_ids` 参数，例如：

```python
memory.propose_core_update(
    scope, "identity", {"名字": "林鸥", "偏好": "猫"}, "用户明确陈述",
    field_evidence_ids={"名字": [name_memory_id], "偏好": [preference_memory_id]},
)
```

后续只修改一个字段时保留其他字段原来的来源。省略字段级来源时，补丁中的字段采用 evidence_ids；旧库也只能沿用版本级的粗粒度来源。引用整条多事实消息可能导致字段保守失效，精确记忆引用能避免误伤无关字段。完全没有来源的旧核心字段不能可靠判断与哪项遗忘有关，系统不会猜测其语义关联。

遗忘会检查当前与历史核心版本的字段来源，将受影响字段屏蔽并追加当前核心清理版本，保留未受影响字段。历史 API 也不再展示受抑制字段；通过相同字段和值重放补丁会被拒绝。原始 SQLite 中的历史 payload 仍可能保留被屏蔽内容，因此这依然是逻辑抑制。移除全部身份字段后，bootstrap 会提示身份恢复不完整。

核心键已迁移：身份 `(user_id,character_id,domain)`，关系再包含 relationship_id，版本分别递增。身份跨同领域关系共享，关系称呼和偏好互相隔离。`None` 关系在核心读取中表示默认关系，不再表示读取其他关系的核心；记忆列表的宽范围查询语义保持原本约定。

## 原子性与在途任务

抑制标记、精确 scope 的 mutation epoch、事实状态、索引/摘要失效和核心清理在同一事务中提交。失败则全部回滚，不留下半份回执。

worker 在计算前捕获 scope epoch，入库前和确认前复核。如果抽取期间另一个 runtime 完成遗忘，旧结果丢弃；仍持有有效租约时释放回 pending，不消耗这次无效计算的尝试次数。下一批从原始事件重算，并逐候选检查抑制标记。这样同消息中未被遗忘的事实仍可处理，不需要取消整条消息的任务。

ConsolidationReport 增加 suppressed（隔离候选数）和 stale_results（丢弃重排的过时结果数）。stale_results 本身不算模型执行失败。即使错误工具把 deleted 行状态重新改为 active，检索校验、核心恢复、摘要和向量路径也会复核账本。

## 迁移与限制

schema v5 → v6 原子增加片段列、抑制表、内容代次和核心字段来源，并重建核心主键。旧记忆 ID、核心版本号和任务保留；迁移后版本按新范围继续递增，旧 deleted 记忆补充抑制标记。核心版本级来源复制到各字段，无法补出历史精确片段。v5 未保存核心 domain，旧核心按历史默认 real 归属；过去混用多世界的库需要显式重新归属，不能推断出丢失的领域信息。

升级时应停止旧版本 worker；旧代码不理解新抑制账本。重复打开不会重复新增抑制标记或清理核心版本。HMAC 密钥与账本应一起备份，恢复较早备份前仍需后续的删除账本同步机制。

事件级 `forget_event` 已实现逻辑传播：写入事件遗忘账本、取消/隔离抽取任务、移除该事件对记忆的来源贡献、没有其他来源时软删除记忆、撤销派生链并屏蔽核心字段；事件正文替换为 `[已删除事件]`。尚未实现：forget_scope 的内容擦除、撤销抑制并明确重新学习、类型化 AND/OR 证据组、宿主旧上下文撤销和备份清理。v0.7 新增了 [HostAdapter 与 MCP 只读接入](host-adapter.md)，v0.9 又增加 DeepSeek Harness 原生生命周期插件；真实模型往返和真实 Harness 遗忘后的上下文撤销仍需验收。相同断言的新消息目前也会被抑制，直到将来提供受控的重新授权入口。full_forgetting 仍为 false。

v0.8 的 [核心候选](core-proposals.md) 在审批前复核来源和遗忘代次，失效候选不应用也不通过检查接口返回旧补丁。候选表的历史字段与理由仍物理保留，未来完整擦除必须覆盖该表。

该机制不执行任意全文语义清理：无来源的活动检查点、核心变更原因等自由文本可能保留同样内容，本地原始事件接口也仍可读取原文。宿主不能把这些内容作为已完成擦除的数据对外重新注入；它们需要后续来源建模与完整删除处理。

测试覆盖新版抽取、重启、重建、原文片段、变更类型/元数据、核心历史、作用域、并发、事务失败、旧库迁移与 CLI 回执。检索质量仍需真实中文语义模型和更大的独立评估集。
