# 实体索引

实体索引是 `memories` 之上的派生投影，用来把结构化正文中的实体名称反查到记忆 ID。它不保存新的事实，也不改变记忆的来源、认识论状态或有效期；最终返回模型前仍必须回表检查作用域、状态和遗忘账本。

## 形成与字段

当前只读取显式结构化字段，避免把整段自由文本中的普通名词误当成实体：

| 字段 | 记忆类型中的用途 |
|---|---|
| `subject`、`obj` | 语义记忆的主客体 |
| `participants` | 情景记忆的参与者 |
| `active_entities` | 工作记忆当前在场的对象 |
| `entities` | 各类型都可提供的显式实体列表 |
| `person`、`location`、`project`、`name` | 抽取器提供的显式命名字段 |

名称会做 Unicode `casefold` 和连续空白折叠，形成 `canonical_name`；`display_name` 保留最近一次出现的表面形式。实体在完整作用域键内唯一，关系、活动和领域之间不会合并。

`entities` 保存名称和计数，`entity_mentions` 保存 `(entity_id, memory_id, role)` 映射。没有剩余提及时，实体行会被清理。记忆接受时增量写入；`MemoryRuntime.rebuild_entities(scope)` 可以从当前有效记忆重建指定作用域及其子范围，适合导入快照、切换抽取器或修复派生表。

## 检索与边界

普通检索增加 `entity` 通道。实体通道只提供候选 ID，随后与关键词、向量和时间通道一起融合，再经过统一的作用域、硬时间、状态、来源和预算校验。双时间历史检索不使用当前实体投影，以免把未来重建的索引泄露到过去视角。

`MemoryRuntime.search_entities(query, scope)` 是宿主侧运维/检索接口，不是默认 LLM 写工具；它只返回实体元数据与记忆 ID，不自动把正文放入上下文。删除或撤回记忆时，相关提及会同步移除；作用域物理清除会删除实体及其提及。作用域快照会同时保存 `entities` 与 `entity_mentions`，因此导入后不需要依赖一次隐式全库重建才能恢复反查关系。

实体索引仍是保守基线：它不负责实体消歧、别名图、跨语言归一化或从自由文本推断实体。后续可以在抽取器输出稳定的 `entity_id`/别名证据后扩展，但必须保持“索引不能提升事实真实性”的约束。
