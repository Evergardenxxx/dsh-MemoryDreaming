# 本地规模基线（2026-10-27）

Windows、Python 3.14，本地临时 SQLite 数据库，合成中文记忆；报告不包含用户数据。运行命令：

```powershell
python scripts/benchmark.py --size 10000 --queries 30
python scripts/benchmark.py --size 10000 --queries 12 --vectors
```

| 场景 | 写入 10,000 条 | 建立 10,000 条向量 | 未缓存查询 p50 | 未缓存查询 p95 | 缓存查询均值 |
|---|---:|---:|---:|---:|---:|
| 未建向量投影 | 5.17 秒 | — | 17.85 ms | 24.70 ms | 1.10 ms |
| 哈希向量完整投影 | 5.13 秒 | 3.50 秒 | 2,877 ms | 3,650 ms | 3.21 ms |

每个未缓存查询不同，缓存查询重复同一查询并核验实际 local_hits。第一种场景不代表语义检索性能；第二种使用默认零依赖哈希向量做全量精确扫描，不代表真实模型质量。实际结果受硬件、向量维度、正文长度和写入并发影响，脚本可重新运行。

已确认瓶颈：全量向量扫描是 O(ND)，一万条时延已明显高于关键词检索。当前缓存可显著减少重复查询成本；更大规模需要另行选择 ANN 投影或分页批量扫描，并保留来源/遗忘校验。此处如实记录观察结果，不将基线测量当作所有规模下的性能承诺。

## v0.27 优化与真实权重

保持默认零第三方运行依赖，移除对每条 float32 向量的重复 Python 类型转换/归一化数组分配；先计算精确分数，再分 128 项批量读取候选和逐条校验遗忘、证据组、去重状态。失效高分候选后继续翻页，不使用会漏掉有效结果的近似上限。向量与最终来源检查共享同一个 WAL 只读快照，稀疏和稠密评分与原完整归一化实现逐项浮点等价。

| 10,000 条完整投影 | 未缓存查询 p50 | p95 / 最大值 | 缓存均值 |
|---|---:|---:|---:|
| 优化前哈希 | 2,877 ms | p95 3,650 ms | 3.21 ms |
| 优化后哈希（12 查询） | 249.63 ms | p95 258.24 ms | 2.39 ms |
| 真实 BGE small 中文 v1.5，512 维（8 查询） | 443.22 ms | 最大 597.64 ms | 未测 |

哈希精确扫描 p50 约改善 11.5 倍。真实 BGE 的 CPU2线程、batch32，加载/编码并构建 10,000 条投影约 44.87 秒。来源、权重摘要与真实评估界限见 [质量验收](quality-acceptance.md)。仍是 O(ND)，本轮修复具体性能瓶颈，不声称已实现 ANN 或任意规模的低延迟保证。
