# 事务外计算与提交前复核（v0.19）

本轮缩短两条主要路径的 SQLite 写事务：后台 extract/dedupe 的向量编码，以及宿主 memory_search、prepare_turn、prefetch 的检索计算。保持原生 Cordis 插件、JSONL bridge 和原有记忆预算，无新增模型工具。

## 后台整理

1. 短写事务领取任务，取得 claim_token；耗时阶段由独立连接心跳续租。
2. 抽取器在事务外产生候选。
3. `read_snapshot()` 读取一致状态、遗忘 epoch 和内容 generation。抽取验证全部候选并构造待写记忆；去重规划规范正文、合并来源/片段以及副本列表。
4. 退出快照后，`VectorIndex.prepare_memories()` 批量编码，得到单次操作内存中的 `PreparedVectors`。此方法拒绝在已有事务中运行。
5. 开短写事务，重新检查租约、scope epoch 和内容 generation。数据未变才写主记录、来源、向量、后续任务和完成确认；任一步失败全部回滚。

`PreparedVectors` 绑定模型 namespace、memory_id 和实际编码正文；`index_memory(..., prepared=...)` 仅复核并存储，不再次调用模型。它不进入持久缓存或模型上下文，也不是授权凭证。写入前仍验证遗忘和状态；正文/模型不一致即拒绝。

计算期间发生来源、遗忘或投影变化时抛 `SourceRevisionChanged`，仍持有租约的任务主动释放、撤回本次尝试计数，下一批重算。租约已失效则直接放弃，不能释放新 worker 的任务。格式/模型/存储失败仍沿原有退避规则处理。任务不会先提交“缺向量的半成品”，旧原子回滚与崩溃恢复保证保留。

代次检查采用全库 generation，其他作用域写入也可能造成保守冲突。这里不会不断内联重算，避免 worker 长时间占用一个任务；繁忙库需要后续细化来源/作用域代次与调度。

## 宿主查询

1. 在短事务中解析可信活动范围、检查本地及共享候选缓存。命中仍逐跳校验 revision、来源、状态及遗忘，并重新签发本会话引用。
2. 未命中时，进入 WAL 只读快照，记录 generation，并完成模型查询编码、各通道检索、融合、预算筛选。该阶段不预占 SQLite 写锁。
3. 退出快照，开短写事务重新检查 generation 和宿主 deadline。数据变化则丢弃全部候选并重新查询，最多执行两次；持续变化时返回可重试 `UNAVAILABLE`，不返回旧正文或伪造完整空结果。
4. 代次一致后使用新的 ViewReader 复核来源、生成引用并写候选缓存。`prepare_turn` 的核心与工作状态也在此最终事务内重新恢复，避免用查询前旧称呼搭配查询后新证据。

`cache_stats().revision_retries` 记录因内容变化丢弃的查询尝试。向量降级规则不变：保留其他通道、标明 partial，降级候选不缓存。计算完成后超过 deadline 也不得发布或缓存；当前本地模型调用仍不能强制打断，所以这不是硬执行超时。

用户事件先独立持久保存。随后查询失败不会抹掉已保存的用户消息，相同 message_id 仍可幂等重试。缓存命中和新检索都在最终短事务内生成响应，模型预算、核心审批和来源权限没有变化。

## 一致读快照

`Database.read_snapshot()` 使用 deferred BEGIN 和 `PRAGMA query_only=ON`，退出时恢复连接设置，异常时回滚。它拒绝嵌入外部事务，禁止内部误写；其他连接在 WAL 模式下可以同时提交，快照继续看到开始时的版本。跨进程/线程仍需独立 SQLite 连接。

写事务仍使用 BEGIN IMMEDIATE 和嵌套 SAVEPOINT；现在 KeyboardInterrupt 等 BaseException 也会回滚，避免中断后遗留未完成事务。

## 验证与剩余边界

新增 16 项回归，验证另一连接在抽取/去重/查询编码期间可以写入，半成品不可见，来源遗忘不能复活，修订后的副本不能按旧聚类合并，租约到期不发布，预计算不能跨正文/模型使用，以及持续修订、deadline、核心变更和预取竞态。既有任务确认/索引/入队失败回滚和子进程崩溃测试继续通过。

全量 428 项 unittest、compileall、Node 插件语法及 diff 检查通过。v0.19 wheel 的 44 个源码/数据文件与仓库一致，独立临时目录安装后完成 observe → consolidate → 宿主 memory_search，创建 1 条记忆并返回 status=ok；内置向量评估也能运行。验证仍使用哈希或可控测试向量，没有运行真实语义模型。

v0.20 已将可信本地同步 `correct(kind='change')` 和变更审批中的结构化替换移到事务外编码，具体复核、重试和回执协议见 [纠错与变更审批](correction-approval.md)。直接调用未传 prepared 的 `index_memory()` 保留旧兼容行为。摘要构建、最终证据验证及缓存检查仍有写事务，后续要用真实规模评估其长度。长只读快照可能延缓 WAL 检查点回收；当前没有取消正在执行的本地模型。真实语义模型和 Harness 主程序验收仍未完成，`full_forgetting` 继续为 false。
