# 检索候选缓存

缓存属于可丢弃的性能投影，不是记忆或授权来源。模型仍只通过原生插件的最小恢复块和按需查询获得资料。

读取顺序：

1. 用可信 SessionBinding 解析查询活动，生成包含作用域、允许活动目录、活动焦点、查询参数、算法版本和嵌入配置的 SHA-256 键。
2. 在同一 SQLite 事务内读取全库内容代次和作用域遗忘代次。
3. 检查本地 TTL、代次、会话事件和来源 revision；本地未命中时再检查 SQLite 候选缓存。
4. 共享命中重新加载候选，逐跳验证来源、状态、作用域及 revision，并签发本会话引用。本地到期时间不晚于共享项原到期时间。
5. 未命中时重新检索，再缓存候选 ID 和 revision。空结果同样受代次约束，新增记忆后必须重查。

`knowledge_at/fact_at` 查询绕过当前投影缓存。引用过期、来源改变或遗忘时仍按原规则拒绝读取；缓存不能延长引用授权。

内容代次由 schema 19 的 SQLite 触发器维护，适用于独立连接和进程。事务回滚恢复代次，缓存读写本身不推进代次。全库代次是保守实现：跨作用域写入会降低命中率。它不代替 TTL 和时间敏感字段复核，也不保证 TTL 内候选排序随时间连续刷新。

持久缓存默认最多 1024 项，每次写入清理过期/旧代次项并按写入时间淘汰；本地 LRU 默认最多 32 项。缓存和 `retrieval_state` 不进入便携快照；导入主记录触发本机内容代次变化。schema 18 升级会丢弃旧缓存中的查询原文，保留全部主记忆；这不承诺擦除历史备份或 SQLite 空闲页。

回归覆盖独立子进程共享与引用隔离、独立连接新增后的负缓存失效、活动/授权/配置分区、原到期时间、容量、事务回滚和旧库重复打开。
